Maintenance

Set up your Google API access

You only do this once. It takes about five minutes and needs a free Google Cloud project. Everything happens between this page and Google — the extension never sends your credentials anywhere else.

  1. Create a project and enable the Gmail API

    Open the Google Cloud Console, create a project (or pick an existing one), then go to APIs & Services → Library, search for Gmail API and click Enable.

  2. Configure the OAuth consent screen

    Go to APIs & Services → OAuth consent screen. Choose External, fill in the app name and your email, and save. While the app is in Testing, add every Gmail account you want to use under Test users — otherwise Google returns 403: access_denied.

    Refresh tokens for a Testing-mode app expire after 7 days, so you would reconnect weekly. Publish the app to avoid that (the verification step is not required for personal use).
  3. Create an OAuth client ID

    Go to APIs & Services → Credentials → Create credentials → OAuth client ID and choose application type Desktop app. A Desktop app client works with the Automatic redirect with no further setup. Copy the Client ID and Client secret.

  4. Paste the credentials into Settings

    Copy the Client ID and Client secret into the Google account section on the Settings tab, then click Connect Gmail.

  5. Approve access

    A Google window opens; pick your account and grant read-only access to Gmail. The window closes by itself when it is done.

Troubleshooting.
  • redirect_uri_mismatch — a Web application client is missing the loopback URI above (or you registered the URL for the wrong client).
  • 403: access_denied — your account is not listed as a Test user on the consent screen.
  • client_secret is missing — paste the Client secret too; Google requires it even with PKCE.
  • Nothing is captured — check the sender filter, the lookback window, and try Rescan mailbox in the popup.
